# 📚 모던 자바스크립트 Deep Dive - 변수

## 변수란 무엇인가?

---

## 메모리란?

메모리는 데이터를 저장하는 공간이다.

- 메모리는 여러 개의 **메모리 셀(Memory Cell)** 로 이루어져 있다.
- 각 메모리 셀은 고유한 **메모리 주소(Address)** 를 가진다.
- 모든 데이터는 메모리에 **2진수(Binary)** 형태로 저장된다.

## 변수가 필요한 이유

만약 메모리 주소를 직접 사용해야 한다면 다음과 같은 문제가 발생한다.

- 메모리 주소를 기억하기 어렵다.
- 주소는 실행할 때마다 변경될 수 있다.
- 잘못된 메모리 주소에 접근하면 시스템에 문제가 발생할 수 있다.
- 재사용성이 떨어진다.

자바스크립트는 개발자가 직접 메모리 주소를 다룰 수 없도록 설계되어 있다.

> C, C++ 같은 언어는 포인터를 사용하여 메모리 주소에 직접 접근할 수 있다.

---

## 변수란?

> 값을 저장하기 위해 확보한 메모리 공간 자체 또는 그 메모리 공간을 식별하기 위해 붙인 이름

```js
let number = 5;
```

여기서 `number`는 값 `5`가 저장된 메모리 공간을 가리키는 이름이다.

---

## 변수는 하나의 값만 저장한다

```js
let number = 5;
```

기본적으로 변수 하나에는 하나의 값만 저장할 수 있다.

여러 값을 저장하려면 객체나 배열을 사용한다.

```js
const user = {
  id: 1,
  name: "user",
};
```

객체 전체가 하나의 값으로 취급된다.

---

## 변수 선언과 할당

### 선언

변수를 생성하는 과정

```js
let result;
```

### 할당

변수에 값을 저장하는 과정

```js
result = 10 + 20;
```

### 선언과 할당을 동시에

```js
let result = 10 + 20;
```

---

## 참조

변수에 저장된 값을 읽는 것을 참조(Reference)라고 한다.

```js
console.log(result);
```

---

# 식별자란?

식별자는 변수, 함수, 클래스 등의 이름을 의미한다.

```js
let result = 30;
```

여기서 `result`가 식별자이다.

식별자는 값을 직접 저장하는 것이 아니라 **값이 저장된 메모리 주소를 기억한다.**

---

# 변수 선언

변수를 사용하려면 먼저 선언해야 한다.

```js
var score;
let count;
const age = 20;
```

변수 선언에 사용되는 키워드

- var
- let
- const

---

# var의 동작 방식

```js
var score;
```

`var`는 선언과 동시에 초기화된다.

내부적으로는 다음과 비슷하게 동작한다.

```js
var score = undefined;
```

---

## 초기화가 필요한 이유

초기화를 하지 않으면 이전에 사용되었던 값이 남아 있을 수 있다.

이러한 값을 **Garbage Value(쓰레기 값)** 이라고 한다.

초기화를 통해 안전하게 `undefined`를 저장한다.

---

# 변수 호이스팅

```js
console.log(score);

var score;
```

실행 결과

```js
undefined;
```

---

## 왜 undefined가 출력될까?

자바스크립트는 코드를 실행하기 전에 **평가 과정(Evaluation Phase)** 을 거친다.

이 과정에서 변수 선언문을 먼저 처리한다.

```js
console.log(score);

var score;
```

실제로는 다음과 비슷하게 동작한다.

```js
var score;

console.log(score);
```

이처럼 선언문이 끌어올려진 것처럼 동작하는 현상을 **호이스팅(Hoisting)** 이라고 한다.

> 실제로 코드가 이동하는 것은 아니다.

---

# 값의 할당

```js
var score;

score = 80;
```

또는

```js
var score = 80;
```

---

## 실행 순서

```js
console.log(score);

var score = 80;

console.log(score);
```

실행 결과

```js
undefined;
80;
```

실행 순서

1. 변수 선언
2. undefined 초기화
3. 값 할당
4. 값 참조

---

# 값의 재할당

```js
var score = 80;

score = 90;
```

변수는 저장된 값을 변경할 수 있다.

이것을 **재할당(Reassignment)** 이라고 한다.

---

## 상수

```js
const score = 80;
```

`const`는 재할당이 불가능하다.

```js
score = 90; // TypeError
```

---

## const 객체는 수정 가능

```js
const user = {
  name: "kim",
};

user.name = "lee";
```

객체 자체를 변경하는 것은 불가능하지만 객체 내부 프로퍼티는 수정할 수 있다.

---

# 가비지 컬렉터

```js
var score = 80;

score = 90;
```

더 이상 사용되지 않는 값 `80`은 가비지 컬렉터(Garbage Collector)가 자동으로 제거한다.

> 제거 시점은 예측할 수 없다.

# 매니지드 언어와 언매니지드 언어

## 매니지드 언어

- 메모리 관리 자동
- 가비지 컬렉터 존재
- 안전성 높음

예시

- JavaScript
- Java
- Python
- C#

---

## 언매니지드 언어

- 메모리 직접 관리
- 성능 최적화 가능
- 메모리 누수 위험 존재

예시

- C
- C++
- Assembly

# 식별자 네이밍 규칙

가능

```js
let userName;
let $name;
let _name;
```

불가능

```js
let 77name;
let if;
```

규칙

- 영문자 사용 가능
- 숫자 사용 가능
- `_` 사용 가능
- `$` 사용 가능
- 숫자로 시작 불가
- 예약어 사용 불가

---

# 식별자 표기법

## camelCase

```js
let userName;
let maxValue;
```

주로 변수와 함수 이름에 사용한다.

---

## PascalCase

```js
class UserProfile {}
```

주로 클래스와 생성자 함수 이름에 사용한다.

---

## snake_case

```js
let user_name;
```

주로 데이터베이스 컬럼명에 사용한다.

---

## kebab-case

```html
<div class="user-profile"></div>
```

주로 HTML, CSS에서 사용한다.

---

## Hungarian Notation

```js
let strName;
let intCount;
```

현재는 거의 사용하지 않는다.

---

# 내가 이해한 방식

변수는 값을 담는 상자가 아니다.

정확히는 **값이 저장된 메모리 공간에 붙인 이름**이다.

```js
let score = 80;
```

위 코드에서 `score`는 `80`을 기억하는 것이 아니라,

`80`이 저장된 메모리 주소를 기억한다.

---

### Q. 변수와 식별자의 차이는 무엇인가?

변수는 값을 저장하기 위한 메커니즘이고

식별자는 메모리 공간에 저장된 값을 구별하기 위한 이름이다.

---

### Q. var가 선언 전에 접근 가능한 이유는?

변수 선언이 런타임 이전 평가 과정에서 먼저 처리되기 때문이다.

---

### Q. 호이스팅이란?

변수 선언문이 코드의 선두로 끌어올려진 것처럼 동작하는 현상이다.

---

### Q. const는 완전히 불변인가?

아니다.

객체나 배열의 경우 내부 값은 변경할 수 있다.

```js
const user = {
  name: "kim",
};

user.name = "lee";
```

---

# 한 줄 요약

- 변수는 값을 저장하기 위한 이름이다.
- 식별자는 메모리 주소를 기억한다.
- var는 선언과 초기화가 동시에 이루어진다.
- 변수 선언은 호이스팅된다.
- 사용하지 않는 메모리는 가비지 컬렉터가 정리한다.
- 변수명은 의미 있게 작성하고 camelCase를 사용하자.
